# FullTank.pk — Pakistan Fuel Cost Calculator (multi-page site with Peto)

A generated static site — many small HTML pages, not one giant page —
organised so a car or bike is always one click from its brand.

## How it's organised
- **`/` (home):** only today's petrol / high octane / diesel price and a
  dropdown calculator (pick Car or Bike → pick the model → pick fuel → see
  the amount). No big list here on purpose, per your request.
- **`/cars/` and `/bikes/`:** hub pages — a grid of every brand, plus a
  browse-by-type row (Petrol/Diesel/Hybrid/PHEV or 70cc/125cc/150cc+/Scooter).
- **`/cars/<brand>.html`, `/bikes/<brand>.html`:** e.g. `/cars/suzuki.html`,
  `/bikes/honda.html` — every model of that brand, sorted cheapest-to-fill
  first, with the full-tank cost **already calculated** next to each one.
- **`/car/<model>.html`, `/bike/<model>.html`:** one SEO-friendly page per
  vehicle (115 of them) with fill-up tables, a "fuel for your budget" table,
  and similar models.
- **`/add.html`:** its own separate page (not on the home page) for adding a
  car or bike that isn't listed. It saves to the visitor's browser and
  immediately shows the calculated cost; it also then appears in the home
  page dropdown and in Peto's matches for that visitor.
- **`/price-history.html`, `/privacy.html`, `/contact.html`.**
- **`/tools.html`:** trip and monthly commute estimates, side-by-side vehicle
  comparisons, EV-versus-fuel running costs, and a browser-local saved garage.

This is generated by `build.js` from `vehicles.json` — **add or edit
vehicles in `vehicles.json`, never by hand-editing files in `dist/`,** since
`dist/` is regenerated from scratch on every build.

## About Peto
A small chat button in the corner of every page. It opens only when tapped
and uses the same fixed, viewport-bounded panel on every page. It asks which
car or bike, matches it by name, asks
Normal/High Octane/Diesel — only offering fuels that vehicle actually takes
— states the amount, then asks if you'd like another. It also guides trip,
monthly commute, EV charging, and vehicle comparison calculations when asked.
Mileage, distance, and electricity rates are supplied by the visitor. It's a fixed
conversation flow in plain JavaScript, not a hosted AI model: a key embedded
in static HTML is visible to anyone who views source, so it would be copied
and abused within hours. It runs locally with no key to leak or renew.

## Fuel tools and saved garage
- The trip and monthly estimator uses the entered km/L, fuel price, daily
  commute distance, and days driven per week.
- Vehicle comparisons show tank size and full-fill cost, plus same-distance
  fuel costs when both real-world averages are entered.
- EV comparisons ask for the vehicle's energy use (kWh/100 km) and the user's
  electricity tariff instead of assuming a universal charging rate.
- Saved vehicles keep the model, preferred fuel, and entered average in browser
  local storage only. They can prefill trip estimates and comparisons.
- Peto offers guided chat flows for these calculations and recognizes requests
  about trips, monthly commutes, comparisons, EV charging, and the local garage.

## Deploying to Netlify (auto-updates daily)
1. Connect this GitHub repository to Netlify and select `main` as the
   production branch. The `netlify.toml` file configures `node build.js` as
   the build command, `dist` as the publish directory, and Node.js 20.
2. The default canonical site URL is `https://fulltankpk.netlify.app`. If you
   use a custom domain, set a `SITE` environment variable in Netlify and a
   `SITE` Actions variable in the GitHub repository to that URL.
3. Enable GitHub Actions for the repository. The daily workflow requests only
   `contents: write` so it can commit price updates; no broader default token
   permissions are needed. Its third-party Actions are pinned to full commit
   SHAs to satisfy the repository's Actions policy.
4. Every day at 12:00 AM PKT, `.github/workflows/daily.yml` runs
   `fetch-prices.js`, commits the new `prices.json`/`history.json`, and that
   push triggers Netlify to rebuild and redeploy from `main`.

Trigger it by hand anytime: repo → **Actions** tab → **daily-fuel-price-update**
→ **Run workflow**.

## About that Google sitelinks / knowledge-panel screenshot
You shared a screenshot of Google showing expandable sub-links (Cloud Console,
Gemini, Account…) and a knowledge-panel card under a search for "Google."
I've added the technical pieces that make a site *eligible* for that kind of
treatment — but I want to be upfront: **no one can turn sitelinks or a
knowledge panel on by writing code.** Both are entirely Google's own
algorithmic call, based on:
- a consistent site structure and real traffic over time (sitelinks),
- and, for the knowledge panel specifically, an established, verifiable
  brand presence (Wikipedia/Wikidata, a Google Business Profile, press
  coverage, etc.) — something that takes months to years to build for a new
  site, not something any code change produces on day one.

What I *did* add, which genuinely improves the odds once the site has
traffic and age:
- **Consistent primary navigation** (Cars / Bikes / Search / Add a vehicle /
  Petrol price) repeated identically on all 168 pages — this is the #1
  signal Google uses to decide what a sitelinks menu should contain.
- **Organization + WebSite structured data** on the home page, naming
  FullTank.pk and describing Peto — this is the same schema type real
  knowledge-panel entities carry.
- **A sitelinks search box**: a working `/search.html?q=...` page plus the
  required `SearchAction` schema, so *if* Google ever shows a search box
  under your listing, it's wired to a page that actually works — try typing
  a car name into the new **Search** link in the nav bar.
- **A real logo** (`logo.svg`) referenced as the favicon and as the
  Organization's logo, since panels/sitelinks pull their icon from there.
- **Peto is now named in the footer, the FAQ schema, and the brand
  description** everywhere, so it's part of the site's "identity" wherever
  Google might pull from.

What actually moves the needle from here is the same as before: backlinks,
consistent daily updates, and time.
